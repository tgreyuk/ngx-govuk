Working with forms

Every form field in ngx-govuk is a native element, such as an input or textarea, inside a form group. The form group adds the label, hint and error message, and connects them to the field.

How a field is built

Add a field directive, such as "ngxGovukTextInput", to a native element and put it inside "ngx-govuk-form-group". The element stays yours: every native attribute and Angular forms directive works as usual.

Showing errors



  Set "errorMessage" when your validation fails. The form group then shows the
  message and adds the error styles to itself and the field. Leave it unset, or
  set it to null, when there is no error.




  GOV.UK's
  validation guidance
  says not to validate when the user moves away from a field. Wait until they
  try to continue, usually by selecting a "Continue" button, as in the example
  above.






Labels



  Use "labelSize" ("s", "m", "l" or "xl") for a bigger label. If a page asks
  just one question, make the label the page heading with "asPageHeading"; it is
  large by default.






Prefixes and suffixes



  Use "prefix" and "suffix" for units, such as currency. Screen readers do not
  read them, so the label must make the unit clear.






Ids and screen readers



  Give each field an "id", so error summaries and labels can link to it. If a
  field has none, the form group generates one.




  The hint and error message get ids based on the field's id, such as
  "email-hint" and "email-error", and the field's "aria-describedby" points to
  them, as in GOV.UK Frontend. Any "aria-describedby" you set on the field is
  kept.
