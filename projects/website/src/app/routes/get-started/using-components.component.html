Using components

ngx-govuk components are standalone Angular components and directives. Import the ones you need into your own components, then use them in your templates.

Import components

Each component has its own entry point, such as ngx-govuk/button, so your app only bundles the components it imports. Import them where you use them, and add them to your component's imports array.

Each component's page shows what to import, in its API section. See the components page for every component.

Native elements

Where GOV.UK's markup is a single element, such as a button, back link or text input, ngx-govuk gives you a directive to add to your own element, rather than a component that draws it. The element keeps all its own attributes, events and Angular directives.

The same goes for elements that do something of their own, such as a details element, which opens and closes, and the nav around breadcrumbs. You write the element, and ngx-govuk draws what goes inside it. Use the element's own attributes and events, such as open and toggle.

Each component's API section shows which elements its directive works on.

Classes and attributes

A component's own element is GOV.UK's outermost element, not a wrapper around it. So an id, class or attribute you add to any component lands where GOV.UK Frontend's styles expect it, including spacing classes such as govuk-!-margin-bottom-0.

Components with parts

Some components are made of several parts, such as an accordion and its sections, or a summary list and its rows. Each part has its own element, and all of them come from the same entry point. Import every part you use.

The API section starts with one import line for everything in the entry point.

Inputs

Set inputs in the usual Angular way.

Inputs are named after the options of GOV.UK Frontend's macros, such as titleText and disableAutoFocus, so GOV.UK's guidance carries over. Where Angular has its own way, ngx-govuk uses it instead:

  • Options with nested text are a single input. GOV.UK's label.text and hint.text are label and hint.
  • Instead of an html option, put the content inside the component.
  • Headings and other short text, such as titleText, are text only: there's no titleHtml or other …Html version. Where a component takes richer text, such as the error summary's description, its API tab says how.
  • Instead of classes and attributes, set classes and attributes on the element as usual.
  • Components the GOV.UK Design System documents on their own go inside the component that uses them. For example, put an error message inside a field rather than setting an option.

Any other input that differs from GOV.UK's option says so in its component's API tab.

Two-way binding

Some inputs change when the user acts, such as the open tab or whether an accordion section is expanded. Bind these both ways to read and set them. Each component's API section lists them as models.

Methods

Some components have methods you can call. Use a template reference variable to reach the component instance.

Links and the router

On a link directive, such as a button or back link, add routerLink to the a element yourself, as above.

Components that draw their own links, such as the service navigation, pagination, footer and task list, take a routerLink value for each link instead, in the same forms routerLink accepts. Your app needs provideRouter for these.

Form fields

Text inputs, textareas, file uploads and selects go inside a form group, which adds the label, hint and error message. See Working with forms.

Checkboxes, radios and the date input add their own legend, hint and error message, so they don't go in a form group. Bind them with formControlName or ngModel like any form control: each ngx-govuk-checkbox is true or false, ngx-govuk-radios is the chosen value, and ngx-govuk-date-input is its day, month and year.
