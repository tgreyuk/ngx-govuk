Working with forms

Most fields in ngx-govuk are a native element, such as an input or textarea, inside a form group. The form group adds the label, hint and error message, and connects them to the field.

How a field is built

Add a field directive, such as ngxGovukTextInput, to a native element and put it inside a form group (ngx-govuk-form-group). The element stays yours: every native attribute and Angular forms directive works as usual.

Reactive and template-driven forms both work. The examples here use formControlName; with template-driven forms, use ngModel on the same element instead.

These fields go inside a form group:

  • Text input (input[ngxGovukTextInput])
  • Textarea (textarea[ngxGovukTextarea])
  • File upload (input[type=file][ngxGovukFileUpload])
  • Select (select[ngxGovukSelect])

Other fields

The character count and password input take the form group's place: put a textarea or input with its field directive inside them, and they add the label, hint and error message as well as their own count or "Show" button.

Checkboxes, radios and the date input are components of their own. They add their own legend, hint and error message, so they don't go in a form group. Bind them with formControlName or ngModel, as in Using components.

Groups of fields

To group related fields under one question, such as the lines of an address, put them in a fieldset, with each field in its own form group. Checkboxes, radios and the date input add their own fieldset, so they don't need one.

Showing errors

Set errorMessage when your validation fails. The form group then shows the message and adds the error styles to itself and the field. Leave it unset, or set it to null, when there is no error.

GOV.UK's validation guidance says not to validate when the user moves away from a field. Wait until they try to continue, usually by selecting a "Continue" button, as in the form group example.

Error summary

When a form has errors, GOV.UK also shows an error summary at the top of the main content, with a link to each field that has an error. Show ngx-govuk-error-summary only when there are errors, and give it the same messages as the fields. Each link's href is # and the field's id.

The summary takes focus when it appears, so screen reader users hear it. Selecting a link moves focus to the field.

GOV.UK also asks you to add "Error:" to the start of the page title, so users hear straight away that something is wrong. Set it with Angular's Title service when the user tries to continue.

Labels

Use labelSize (s, m, l or xl) for a bigger label. If a page asks just one question, make the label the page heading with asPageHeading; it is large by default.

Prefixes and suffixes

Use prefix and suffix for units, such as currency. Screen readers do not read them, so the label must make the unit clear.

Ids and screen readers

Give each field an id, so error summaries and labels can link to it. If a field has none, the form group generates one.

The hint and error message get ids based on the field's id, such as email-hint and email-error, and the field's aria-describedby points to them, as in GOV.UK Frontend. Any aria-describedby you set on the field is kept.
