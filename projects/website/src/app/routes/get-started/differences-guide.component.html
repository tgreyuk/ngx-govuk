Differences from GOV.UK Frontend

ngx-govuk renders the same markup as GOV.UK Frontend, so GOV.UK Frontend's styles apply unchanged. How you set components up, and how they behave, is done the Angular way instead.

GOV.UK Frontend's JavaScript is not used

Components that do something, such as the accordion, tabs, character count and exit this page, do it in Angular. They do not have GOV.UK Frontend's data-module attributes, and they do not need its JavaScript or initAll().

GOV.UK's page template adds classes to the page, including govuk-frontend-supported, which it sets with a small inline script and some of GOV.UK Frontend's styles depend on. provideNgxGovuk() adds them instead. See Add the ngx-govuk provider.

GOV.UK Frontend's JavaScript configuration, such as the text it adds for screen readers, is a set of inputs on the component instead. For example, the password input's showPasswordText.

Options are Angular inputs

The options of GOV.UK Frontend's Nunjucks macros are inputs with the same names, with a few changes:

  • Nested text options are a single input, such as label for label.text.
  • Content goes inside the component instead of in an html option.
  • You set classes and attributes on the element instead of with classes and attributes.
  • Where GOV.UK's markup is a single element, such as a button, you add a directive to your own element instead of using a component.
  • Components the GOV.UK Design System documents on their own, such as the error message, go inside the components that use them.

Using components explains each of these. Any other input that differs from GOV.UK's option says so in its component's API tab.

Forms use Angular forms

Fields work with reactive and template-driven forms. Text inputs, textareas, file uploads and selects go inside a form group, a component ngx-govuk adds, which renders their label, hint and error message. Checkboxes, radios and the date input are form controls themselves. See Working with forms.

Links use the router

Components that render their own links, such as the service navigation, pagination and task list, take a routerLink value for each link, where GOV.UK Frontend takes an href. Some also take an href for links outside your app. See Links and the router.

Behaviour that differs

  • The accordion does not remember which sections were open when the page reloads, as GOV.UK Frontend does. Bind each section's expanded to keep it yourself.
  • Tabs can open routes as well as panels on the page. See the tabs examples.

Not included

  • GOV.UK Frontend's page template. provideNgxGovuk() adds its classes, and you lay out the page in your root component, as in Lay out the page.
  • Options for the classes and attributes of a component's inner parts, such as a radio's label classes or an item's attributes.
  • …Html versions of headings and other short text, such as titleHtml.
  • idPrefix on radios and checkboxes. Item ids come from the group's name, as they do in GOV.UK Frontend when there is no prefix.
  • Translations for the accordion's buttons, which are in English only.

To ask for something that is missing, raise an issue on GitHub.
